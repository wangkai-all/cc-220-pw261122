# 合同收入递延计划 · 演示工具

一个纯静态网页，用于按**明示的简化规则**把合同数据（服务起止时间、履约项目、合同价格、
开票收款、变更记录）换算成各期收入确认计划、递延收入余额，并支持版本对比与明细导出。

> **免责声明：本工具是规则演示与算术核对工具，不构成任何会计准则下的会计处理意见或合规结论。**
> 真实合同的收入确认需要专业人员结合合同条款判断。页面内置合同与数据全部为虚构。

## 运行

无需构建，任选一种：

```bash
# 方式一：直接用浏览器打开 index.html（推荐用下面的本地服务器，避免个别浏览器的 file:// 限制）
# 方式二：本地静态服务器
npm start          # http://localhost:8080
python3 -m http.server 8080
```

```

data/samples.js       三份虚构合同样例
tests/engine.test.js  Node 单元测试
```

## 支持的计算规则（摘要，完整版见页面「规则说明」页签）

1. **独立售价（SSP）分摊**：组合合同按各项目 SSP 占比分摊合同价；各项四舍五入到分，
   舍入尾差并入最后一项，原值、权重、尾差去向全程保留可追溯。未配置 SSP 时兜底均分。
2. **服务按天履约**：起止区间含首尾两天，闰日自然计入（如 2024-02 为 29 天）；
   月度收入 = 分摊价 × 当月履约天数 / 总天数，月尾差并入最后一个履约月。
3. **商品按确认交付日履约**：交付日所在月一次性确认全部分摊价。
4. **变更与版本**：延长 / 部分终止 / 追溯调价各生成一个新版本；
   **锁定月 = 生效日上一个自然月，锁定月及以前的已确认收入任何规则下都不改写**（表中阴影行）。
5. **两种更正规则（逐笔可选）**
   - **未来适用法 prospective**：新分摊价 − 已确认 = 待确认余额，在剩余服务天数内重新按天摊销；
     若项目已在锁定月前履约完毕、没有未来期间可承接价格增量，该增量作为明示的「未来适用调整」
     计入变更生效月（不回写历史）；
   - **累计追补法 catchup**：按新条件完整重算，锁定月以前的新旧差额作为一条
     「累计追补调整」计入变更生效月，历史月份本身不改写。
6. **开票与收款是独立结算事实**：红冲开票、退款打款以**负数**录入；每个计划版本只纳入
   下一版变更生效日之前已发生的现金/结算记录（末版含全部），历史版本不被后来发生的事实穿越改写。
   - 递延收入余额 = 累计开票 − 累计确认收入；
   - 应收余额 = 累计开票 − 累计收款。
7. **金额口径**：元、两位小数；内部按完整精度计算，仅在月度确认点与展示处舍入，尾差有明确承接行。

## 虚构样例覆盖的场景

| 合同 | 覆盖点 |
|---|---|
| 合同一 跨年云订阅 | 跨年度服务、追溯调价、累计追补法、追补调整行 |
| 合同二 软件许可+运维组合 | SSP 比例分摊与尾差、商品交付日确认、2024 闰日按天、合同延长 + 未来适用法、跨年到 2027 |
| 合同三 驻场服务部分终止 | 部分终止、部分退款（负数开票/负数收款）、锁定期间不改写、递延与应收期末归零 |

## 数据导入导出

- **JSON**：整库导出/导入（页面导出格式）。
- **CSV**：单合同多区块文本，区块标记为 `#contract / #obligations / #invoices / #collections / #changes`，
  可用表格软件编辑后导回。
- 月度计划与版本对比可各自导出 CSV。
- 数据仅保存在当前浏览器 localStorage，不上传任何服务器。

## 明确不做的事

- 不提供会计准则适用性判断或合规结论；
- 不处理可变对价估计、重大融资成分、合同合并/分拆判断等专业议题；
- 不做多人协作与服务端存储。
